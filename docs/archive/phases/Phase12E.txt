Core doctrine:

- Shadow mode observes and reports only.
- Shadow diagnostics are non-authoritative.
- Shadow diagnostics must not affect live response behavior.
- Shadow diagnostics must not mutate live state.
- Shadow diagnostics must not execute tools.
- Shadow diagnostics must not call modelruntime.
- Shadow diagnostics must not perform retrieval/search/embedding calls.
- Shadow diagnostics must not write memory.
- Shadow diagnostics must not call controllane mutations.
- Shadow diagnostics must not create a second authority path.
- `FORGE_K_SHADOW_MODE_ENABLED` remains disabled by default.
- `/health` remains supported.
- Route envelope metadata is the only new live observation category.

Route envelope metadata allowed:

- HTTP method
- request path pattern or route pattern, if safely available
- normalized route class
- workspace/correlation/request id if already available in safe metadata
- status code only if already captured without changing response behavior
- timing duration
- shadow observation timestamp
- bounded warning strings
- diagnostic-only metadata

Route envelope metadata forbidden:

- request body
- response body
- prompt text
- model output
- file contents
- source chunks
- retrieval result content
- user secrets
- auth headers
- cookies
- bearer tokens
- API keys
- raw authorization metadata
- large raw content blobs

Preferred implementation strategy:

- Extend `services/core/internal/forgekshadow` with route envelope observer support.
- Keep `services/core/internal/forgek/...` pure and free of live imports.
- Add a narrow API-level middleware or wrapper only if it can prove no behavior change.
- Prefer observing after response is written.
- Avoid response writer wrapping unless needed and well-tested.
- If status code capture requires risky wrapping, skip status code in this phase.
- Keep reports in the existing bounded in-memory diagnostic sink.
- Keep the feature flag disabled by default.
