# FORGE PhaseI2 — Live KV Identity Enforcement & Observation

You are working inside the FORGE repository.

PhaseI1 is complete enough to count as landed.

PhaseI1 delivered:

- shared deterministic KV identity validation in `services/core/internal/kvidentity`
- simulator FORGE-K usage of the shared pure validator
- live AI-OS Control Lane support for `VALIDATE_KV_IDENTITY`
- capability registration for `kv.identity.validate`
- explicit status that this is `[PARTIAL] LIVE VALIDATION / NO LIVE KV REUSE`
- docs explaining the simulator-to-live migration pattern

PhaseI2 must build on that seam.

Do not make FORGE-K live.
Do not enable live KV reuse.
Do not allow simulator packages to become live authority.
Do not add new mythology.

## Phase Name

PhaseI2 — Live KV Identity Enforcement & Observation

## Mission

Turn PhaseI1's live KV identity validation seam into a real live enforcement and observability layer.

PhaseI1 proved:

> the live daemon can validate KV identity deterministically.

PhaseI2 must prove:

> live daemon paths that make KV/cache/runtime identity claims cannot bypass deterministic KV identity validation, and those validation decisions are observable, auditable, and testable.

This is still not live KV reuse.

This is still not FORGE-K live authority.

This is live guardrail enforcement.

## Hard Boundaries

The following must remain true:

- FORGE-K remains simulator-only unless explicitly marked otherwise.
- FORGE-K `KVService` must not become live daemon authority.
- `services/core/internal/kvidentity` must remain pure and deterministic.
- No model runtime mutation may be introduced.
- No memory mutation may be introduced.
- No backend cache reuse may be introduced.
- No public KV reuse API may be introduced.
- No simulator package may import live daemon packages.
- FORGE-H remains immutable.
- Rule/autonomy agents remain propose-only.
- All live authority must continue through existing gateway / Control Lane / permissions / lane / audit boundaries.
- Any rejected validation must fail closed.

## Goal

Add enforcement and observation around live KV identity validation.

By the end of PhaseI2, the live daemon should have:

1. A clear policy boundary for KV identity validation.
2. Enforcement hooks where live code accepts or processes KV/cache/runtime identity-related claims.
3. Structured audit output for validation decisions.
4. Metrics or counters for validation accepted/rejected/error paths.
5. Strong tests proving bypasses fail.
6. Updated doctrine showing PhaseI2 as `[PARTIAL LIVE ENFORCEMENT]`, not live KV reuse.

## Workstream 2 — Add Live Enforcement Policy

Create a small live-side enforcement layer that wraps the shared pure validator without putting policy into the pure package.

Preferred location:

`services/core/internal/aios/controllane`

or a nearby internal live package if the existing architecture has a better home.

Possible names:

- `kvenforcement`
- `kvpolicy`
- `identitypolicy`
- `controllane/kvenforcement`

Use the existing project naming style.

The enforcement layer should:

- call `services/core/internal/kvidentity`
- classify results as accepted, rejected, malformed, unsupported, or internal error
- return deterministic decision objects
- carry enough structured fields for audit/log/metric use
- never mutate memory
- never mutate runtime
- never reuse KV cache
- fail closed on invalid or ambiguous input

Example decision fields:

- `accepted`
- `reason`
- `identity`
- `source`
- `accelerationOnly`
- `memoryMutation`
- `runtimeMutation`
- `liveKVReuse`
- `validatorVersion`
- `policyVersion`

Do not make this a giant framework.

Make it boring. Boring is beautiful. Boring does not wake us up at 3 AM.

## Workstream 3 — Enforce Validation Before Accepted Live Identity Claims

Find the safest live path where KV/cache/runtime identity claims are accepted or summarized.

At minimum, enforce policy inside the existing live Control Lane `VALIDATE_KV_IDENTITY` flow.

If there are other live-facing handlers/capabilities that accept related identity claims, route those through the enforcement layer too.

The enforcement behavior must be:

- valid identity claim: accepted, audited, counted
- invalid identity claim: rejected, audited, counted
- malformed input: rejected, audited, counted
- unsupported live reuse request: rejected, audited, counted
- ambiguous request: rejected, audited, counted

The response must remain honest:

- `accelerationOnly: true`
- `memoryMutation: false`
- `runtimeMutation: false`
- `liveKVReuse: false`

Unless the code truly implements otherwise, which PhaseI2 must not do.

## Workstream 6 — Tests

Add focused tests.

Required test coverage:

### Pure validator tests

For `services/core/internal/kvidentity`:

- stable deterministic output for same input
- different identity material produces different identity result
- malformed input rejected
- empty input rejected
- unsupported claim type rejected if applicable
- no time/random/global state dependency

### Live enforcement tests

For the new enforcement layer:

- valid identity claim accepted
- invalid identity claim rejected
- malformed claim rejected
- unsupported live KV reuse request rejected
- ambiguous request rejected
- decision object preserves `memoryMutation=false`
- decision object preserves `runtimeMutation=false`
- decision object preserves `liveKVReuse=false`
- fail-closed behavior on validator error

### Control Lane tests

For `VALIDATE_KV_IDENTITY`:

- action routes through enforcement layer
- valid request succeeds
- invalid request fails cleanly
- rejection does not mutate state
- audit event emitted for accepted request
- audit event emitted for rejected request
- metrics/counters increment for accepted request
- metrics/counters increment for rejected request
- transaction behavior remains correct
- unauthorized caller cannot bypass validation

### Boundary tests

Confirm:

- simulator package cannot import live daemon packages
- live daemon does not import simulator-owned `KVService`
- FORGE-H mutation guard still passes
- rule/autonomy agents remain propose-only
- gateway-only tool execution remains enforced
