Goal:

Build the FORGE-K runtime driver boundary inside `services/core/internal/forgek`.

Phase 9 should define model runtimes as governed drivers, not authority.

This phase adds:

- RuntimeDriver interface
- RuntimeDriverManifest
- RuntimeCapabilityManifest
- RuntimeGenerateRequest
- RuntimeGenerateResult
- RuntimeDriverRegistry
- MockRuntimeDriver for tests
- RuntimeService or RuntimeBroker
- Runtime syscalls
- Integration with ContextBundle and KV identity metadata by reference only
- Tests proving model/runtime output is proposal evidence only and cannot mutate canonical truth

Core doctrine:

- Models are drivers, not authority.
- Runtime drivers generate outputs but do not own truth.
- Runtime output is proposal/evidence until admitted/committed by existing FORGE-K mechanisms.
- Runtime drivers must not mutate Kernel objects directly.
- Runtime drivers must not bypass semantic syscalls.
- Runtime drivers must not admit evidence.
- Runtime drivers must not write snapshots, context blocks, or KV manifests directly.
- Runtime drivers may report capabilities.
- Runtime drivers may accept ContextBundle references or canonical prompt text from the Context Compiler.
- Runtime drivers may receive KV lookup metadata, but Phase 9 must not perform real backend KV reuse.
- Runtime generation must be deterministic in tests via mock drivers.
- No live daemon integration in this phase.
