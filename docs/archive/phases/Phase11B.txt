Goal:

Create a small Rust validation crate for deterministic FORGE-K primitives.

The crate should validate and hash fixture JSON for stable simulator artifacts.

Initial Rust-owned primitives:

- canonical JSON normalization for selected fixture inputs
- SHA-256 hash generation over canonicalized data
- snapshot shape validation
- context block validation
- KV cache manifest validation
- runtime driver manifest validation
- capability-like permission shape validation, if stable enough
- CLI command for validating fixture files

Do not port the whole Go simulator.

Deliverables:

3. Implement canonicalization.

Rules:

- stable key ordering
- stable array ordering only where the schema declares unordered refs
- normalized whitespace
- deterministic JSON output
- no timestamp-dependent hash input
- no random IDs generated by Rust
- preserve explicit IDs from fixtures
- reject non-object roots for manifest validation

Use serde/serde_json.

4. Implement hashing.

Use SHA-256.

Functions:

- hash_canonical_json
- hash_snapshot_shape
- hash_context_block
- hash_context_bundle
- hash_kv_manifest_identity
- hash_runtime_manifest

Rules:

- hash only stable fields
- exclude created_at / updated_at / journal_refs unless explicitly part of identity
- document each hash input field set

5. Implement validators.

Validate:

SnapshotManifest:
- snapshot_id present
- snapshot_type valid
- workspace_id present
- status valid
- source refs or operation refs present unless type allows empty
- shape_hash present or computable
- no large raw content field
- snapshots are shape, not truth

ContextBlock:
- block_id present
- block_type valid
- workspace_id present
- source refs present
- content_hash or canonical_text present
- token_input_hash present or computable
- cache eligibility valid
- context block is shape, not truth

ContextBundle:
- bundle_id present
- workspace_id present
- layout_version present
- blocks non-empty
- bundle_hash present or computable
- stable_prefix_hash present or computable
- volatile_suffix_hash present or computable

KVCacheManifest:
- cache_id present
- cache_mode valid
- workspace_id present
- bundle_id or block_id present
- model_id present
- model_revision present
- tokenizer_id present
- tokenizer_revision present
- chat_template_hash present
- prompt_layout_hash present
- policy_schema_hash present
- syscall_schema_hash present
- token_input_hash present
- runtime_backend present
- runtime_version present
- attention_backend present
- rope_config_hash present
- kv_precision present
- cache_salt present
- memory_tier valid
- status valid

RuntimeDriverManifest:
- driver_id present
- driver_kind valid
- runtime_backend present
- runtime_version present
- no secret-looking fields or values
- declared capabilities are metadata only
- manifest does not grant authority

6. Implement secret-looking field rejection.

Reject fields or string values that look like:

- api_key
- secret
- token
- password
- private_key
- bearer
- plaintext

Make this conservative and documented.

This is for manifests only. It is not a full secrets scanner.
