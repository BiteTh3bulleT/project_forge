## Mission

Verify, harden, and polish the FORGE desktop shell so it behaves like a real operator desktop, not a dashboard inside Linux.

FORGE currently runs as a desktop shell on top of the labwc Wayland compositor substrate. labwc owns low-level compositor behavior. FORGE owns the operator-facing desktop surface, launcher, taskbar, shell windows, native app visibility model, bounded native-window controls, and session UX.

This phase does not replace labwc.
This phase does not create a compositor.
This phase makes the existing shell trustworthy under real operator use.

## Goals

### 1. Verify Current Desktop Shell Behavior

Audit the current implementation against intended OS-shell behavior.

Confirm:

* closed native apps disappear from the taskbar
* failed launches do not leave phantom entries
* multiple terminal windows remain separate
* multiple file-manager windows remain separate
* focused/minimized/restored state updates correctly
* taskbar does not treat stale polling output as truth
* frontend consumes backend/compositor lifecycle truth
* clean boot lands on the desktop, not diagnostics
* System/Status remains available but not noisy by default

Create or update:

* docs/reports/phase_g8_desktop_shell_verification.md
* docs/status/phase_g8_desktop_shell_verification.md

### 2. Native App UX Polish

Improve operator-facing behavior for native Linux apps.

Requirements:

* terminal launcher should prefer configured terminal
* file-manager launcher should prefer configured file manager
* browser launcher should use configured/default browser when available
* unsupported native actions must fail visibly and safely
* native app taskbar labels should be human-readable
* native app icons should use known mappings where possible
* unknown app icons should use a clean fallback
* native app windows should not collapse into one confusing entry unless explicit grouping exists
* launch failures should produce bounded diagnostics, not ghost entries

Do not introduce unsafe shell execution.

Do not execute arbitrary command strings.

### 3. Start Menu / Launcher Polish

The Start/launcher surface should feel like an OS launcher.

Requirements:

* common operator apps are easy to launch:

  * terminal
  * files
  * browser
  * system/status
  * settings
  * activity/jobs
  * memory
  * chat/workspace
* failed launches show bounded diagnostics
* launcher does not spam duplicate pending entries
* launcher does not expose unsafe host mutation controls
* launcher labels are clear and operator-friendly
* launcher favorites/pinned apps remain stable after restart if already supported

### 4. Taskbar Interaction Verification

Verify or implement expected behavior:

* left click:

  * focus/restore inactive window
  * minimize active focused window when appropriate
* middle click:

  * close when supported
* right click:

  * open a bounded action menu with available actions:

    * focus/restore
    * minimize
    * maximize/fullscreen if supported
    * close if supported

Unsupported actions should be hidden or disabled.

No fake controls.
No demon buttons.
No “it probably works” buttons. Civilization has suffered enough.

### 5. Clean Desktop Boot

Ensure normal boot flow remains:

* FORGE loading screen
* FORGE login when enabled
* empty desktop after login
* wallpaper/dock/taskbar/start visible
* no restored clutter unless explicitly configured
* diagnostics hidden behind System/Status/Activity

If forge-core is unreachable, show honest degraded state without pretending everything is healthy.

### 6. Operator Smoke Test Runbook

Create or update:

* docs/runbooks/desktop_shell_operator_smoke_test.md

Include manual checks:

* boot to desktop
* open terminal
* open two terminals
* close one terminal
* close both terminals
* open file manager
* open browser
* left-click taskbar entries
* middle-click taskbar entries
* right-click taskbar entries
* minimize/restore native apps
* close native apps
* restart shell
* verify no stale taskbar entries
* verify degraded System/Status state if core is stopped
* verify normal desktop/session rollback remains available

### 7. Tests

Add or update focused tests for:

* terminal preference resolution
* invalid terminal config rejection
* file-manager preference resolution if supported
* browser preference resolution if supported
* native launch pending expiration
* duplicate pending launch prevention
* taskbar entry removal after close
* multiple native windows represented separately
* clean desktop reset after login
* right-click menu action availability
* no unsafe shell string execution
* no direct host mutation commands introduced

Use existing repo conventions.

Prefer focused tests over huge fragile integration tests unless the repo already has stable integration coverage.
