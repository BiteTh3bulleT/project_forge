3. Create docs/adr/0006-rust-kernel-core-boundary.md

ADR format:

# ADR 0006 - Rust Kernel Core Boundary

Status: Proposed or Accepted, whichever is appropriate based on findings.

Context:

- FORGE-K Phase 1-10 exists as Go simulator authority.
- Rust may be valuable for deterministic kernel primitives.
- The live daemon is still not FORGE-K-governed.
- Rust must not become a second ungoverned authority path.

Decision:

Prefer a Rust library boundary for deterministic validation primitives only.

Initial Rust candidates:

- canonical serialization
- hashing
- manifest validation
- capability check primitives
- journal integrity primitives
- KV nine-gate validation primitives

Non-goals:

- no live daemon integration
- no model runtime calls
- no gateway/tool execution
- no route/API changes
- no replacement of Go simulator yet

Consequences:

Positive:
- stronger invariant enforcement
- clearer stable kernel contracts
- easier future hardware/software co-design path
- better deterministic test corpus

Negative:
- adds language/tooling complexity
- requires stable serialization contracts
- can slow development if started too early
- FFI boundary must be carefully tested

Alternatives considered:

- keep everything in Go
- rewrite all FORGE-K in Rust
- start with Rust daemon
- start with tiny Rust validation library
